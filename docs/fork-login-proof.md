# Disposable GNOME login proof

`scripts/qualify-fork-login.py` checks a typed GDM password and the rendered
wallpaper in a separate, nonpublished VM. Run it after the native canary build.
It accepts only the GNOME images for Yellowfin or Grouper made by
`scripts/qualify-fork-image.py`.

```bash
sudo python3 scripts/qualify-fork-login.py \
  --image localhost/fork-qualification/yellowfin:gnome-linux-amd64 \
  --wallpaper /path/to/qualification/wallpaper.jpg \
  --output /path/to/qualification/login
```

Use a fresh output path. The host needs the pinned Corral, Podman, OpenSSL, SSH,
Python with Pillow and PyYAML, and Tesseract (`tesseract-ocr` on Ubuntu runners).
It needs the same root, loop-device and QEMU setup as the existing Corral boot
gate. It refuses a connected Tailscale interface: the test guest's SSH and VNC
must bind to loopback. Run it on an isolated, disposable CI runner.

## Evidence and limits

The script records the source image ID and digest, then pins that image under a
unique local tag. Corral builds a separate image with a locked `canary`
account and the run's public SSH key. No password or password hash enters the
source image, derived image, image build context, or build cache. After boot, an
ephemeral SSH key sets a random password hash in the disposable guest. The
password is never printed or passed in a command argument.

The test uses QMP keyboard events to select the visible account and type its
password. It needs both the account name and the Password prompt in OCR
before it types the secret. It does not add autologin, alter GDM/PAM, start a
user session through SSH, or enable passwords for SSH.

A pass needs all of these observations:

1. No graphical `canary` session before keyboard input.
2. A new local session on seat0. It must be active and unlocked, with
   `gdm-password` as its authentication service. The test account must own a
   process for GNOME Shell.
3. The same boot ID before and after input, and a session timestamp after input
   preparation.
4. The logged-in user's effective light and dark wallpaper settings select the
   canary image. A screenshot, paired with that session, shows the solid canary
   wallpaper over at least half the central screen region.
5. Removal of the VM, derived image, temporary source tag and private key files.

The wallpaper check is limited to the solid fixture generated by the native
qualification script. It rejects other pictures. A welcome dialog or an open
window can cover the desktop and fail this check even when typed
login passed. The two verdicts remain separate.

`login-proof.json`, the before/after logind observations, PNG screenshots and
serial console are safe evidence outputs. The script removes raw Corral files from its private
temporary directory. Do not upload a Corral `ssh/` directory or
its generated image layer. A cancelled or killed runner still needs its normal
disposal policy. The script handles SIGTERM, but SIGKILL cannot run cleanup.

This qualifies the disposable derived canary's observed login path. It does not
claim that an unmodified release image contains a usable account. The receipt
keeps `production_image_login_qualified` false.

## Integration

Install `tesseract-ocr` with the workflow's existing test tools. Run the command
above for each successful native build, using that build's local image and
wallpaper fixture. Copy only its output directory into the bounded artifact
bundle. Read `typed_login` and `wallpaper_render` from `login-proof.json`; do not
replace either verdict with Corral readiness or an SSH result.

The script is additive and does not change the production admission gate. It
starts a second VM because the ordinary boot gate deletes its VM on exit.

## Troubleshooting

| Symptom | Measured constraint | Action |
| --- | --- | --- |
| Local image lookup attempts a registry pull | Corral commit `388342bec8a54e4c09e265f41fcea4d92597ea47`, `pkg/bootc/local.go`, admits `localhost/` and `containers-storage:` as local refs; a bare image ID is not one. | Use the harness's unique local source tag and preserve its image-ID receipt. |
| A login test reports readiness without testing a password | The same Corral commit's `pkg/vmtest/run.go` reports readiness through SSH or a console marker. Neither reports GDM authentication. | Require the separate keyboard-input, logind and framebuffer observations. |
| Password material appears in retained test artifacts | Corral's `cmd/vmtest.go` and `pkg/vmtest/result.go` can include a supplied account password; `pkg/vmtest/layer.go` also enables SSH password auth when one is supplied. | Keep `users[].password` absent; set the password only in the booted disposable guest and do not retain raw Corral files. |
